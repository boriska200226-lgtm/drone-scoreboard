# «Гильдия» — закрытая RPG-платформа класса

Раздел `/guild` этого проекта. Живёт рядом с «БАС Ареной» (`/`) и не пересекается
с ней ни кодом, ни базой: у «Арены» остались её serverless-функции, у «Гильдии»
собственный сервер, потому что реальное время требует долгоживущих соединений.

```
backend/guild-server/     FastAPI + PostgreSQL + WebSocket
  app/rules.py            вся игровая арифметика, без БД и HTTP
  app/service.py          операции над классом: СЗ, Броня, Древо, Фестиваль
  app/hub.py              комнаты WebSocket, широковещание
  app/routers/            auth · guild (публичное) · hero (ученик) · teacher · ws
  migrations/             схема БД
  tests/                  120 тестов
src/guild/                фронтенд раздела
  ws.ts                   сокет + переподключение + REST-fallback
  sound.ts                свисток (Web Audio) и вибрация
  pwa.ts                  установка приложения и Service Worker
  components/             Алтарь, Карта героя, Тихая почта, панель учителя, карточки
public/sw.js              Service Worker: кэш на 7 дней, офлайн
public/manifest.webmanifest
deploy/                   nginx + Dockerfile фронтенда
docker-compose.yml        db + api + web одной командой
```

Разворачивание и API — в [`backend/guild-server/README.md`](backend/guild-server/README.md).

## Ответы на пять вопросов из ТЗ (§11)

### 1. PWA — установка, офлайн, манифест, Service Worker

`public/manifest.webmanifest`: `display: standalone`, `theme_color: #2b4b3b`,
иконки 192/512 плюс отдельная maskable. Браузер предлагает установку сам;
если он этого ещё не сделал, в интерфейсе есть своя кнопка «Установить»
(`src/guild/pwa.ts` перехватывает `beforeinstallprompt`). На iOS
`beforeinstallprompt` не существует, поэтому там показывается подсказка про
«Поделиться → На экран “Домой”».

`public/sw.js` держит три кэша: оболочку приложения, статику (7 дней,
stale-while-revalidate) и последний ответ `GET /api/guild/state`. Навигация
идёт network-first: есть сеть — свежая страница, нет сети — последняя
загруженная. Ничего чужого домена и ни одного изменяющего запроса кэш не
трогает.

Проверено в реальном Chromium: Service Worker регистрируется и берёт страницу
под контроль, после отключения сети `/guild` отдаёт HTTP 200 из кэша.

### 2. WebSocket — события, вибрация, переподключение, fallback

`wss://<домен>/ws?token=…` на том же домене, что и сайт (см. `deploy/nginx.conf`),
поэтому ни CORS, ни смешанного контента не возникает.

События ровно те, что в ТЗ: `souls_updated`, `armor_changed`, `debuff_applied`,
`festival_ready` (плюс служебные `state` и `pong`).

Обрыв: клиент раз в 3 секунды пробует подключиться заново и одновременно
опрашивает `GET /api/guild/state` раз в 5 секунд. Значок в шапке честно
показывает, какой канал сейчас работает: «реальное время» или «резервный канал».

Проверено в браузере: при полностью заблокированном WebSocket Алтарь
наполняется всеми 25 героями, значок переключается на «резервный канал»,
опрос идёт с интервалом 5 секунд.

### 3. Docker — школьный ноутбук или VPS

`docker compose up -d --build` из корня поднимает PostgreSQL, сервер и nginx
со собранным фронтендом. Миграции накатываются при старте. Данные — в
именованном томе. Ничего наружу, кроме одного порта (`WEB_PORT`, по умолчанию
8080), не торчит.

Для 152-ФЗ важно, что вся связка ставится on-premise: наружу приложение не
ходит ни за чем — ни за шрифтами API, ни за телеметрией.

### 4. Прогноз Фестиваля — сколько СЗ осталось, без имён

`GET /api/guild/festival/forecast` отдаёт: текущий процент Древа, порог,
сколько СЗ не хватает классу и сколько это примерно на одного героя. В ответе
нет ни кличек, ни идентификаторов — только числа. То же самое видит и ученик
на вкладке «Фестиваль».

Расчёт округляется вверх: если до 70% не хватает 233.1 СЗ, показывается 234,
иначе класс «добрал бы» и не открыл Фестиваль.

### 5. Свисток — звук на всех устройствах за секунду

Кнопка учителя → `POST /api/teacher/whistle` → широковещание в комнату класса.
Клиент синтезирует судейский свисток через Web Audio (две гармоники плюс
трель — никакого файла тянуть не надо) и вызывает `navigator.vibrate(100)`.
Один свист — «СТОП-ИГРА», два — «РАЗБОР».

Замерено в браузере: **66 мс** от клика учителя до вспышки на экране ученика.

Звук требует первого касания экрана — это ограничение браузеров, не наше.
Поэтому аудиоконтекст разблокируется на первом же тапе, начиная с кнопки входа.

## Механика: что именно реализовано

| Механика | Где | Проверка |
| --- | --- | --- |
| СЗ: доброе слово +2, перевод мата +5, помощь троим +3, рука +1, чит-код +10 (3/нед) | `rules.SOUL_ACTIONS` | лимит чит-кода проверяется по последним 7 дням |
| 4 шкалы Карты героя, цвет ≥80 🟢 / 50–79 🟡 / <50 🔴 | `rules.bar_color`, `components/ProgressBar.tsx` | тап раскрывает подпись, мигание в зоне 65–75% |
| Броня: 0–1 прогул +1, 2 → 0, 3 → −2 и −5% Древа, 4+ → −4, −10% и «Слабость» 3 дня | `rules.armor_outcome` | уважительная не считается; повторный запуск за тот же день ничего не делает |
| Древо: бонусы на 50/70/85/100%, цвета серая → синяя → жёлтая → зелёная | `rules.tree_*` | конфетти при переходе через 70% |
| Ветки Тактика / Дипломатия / Хранитель, бонусы на 80% и 100% | `rules.BRANCHES` | кличка привязана к ветке при выдаче |
| Дебафф «мат»: −10% Древа, 24 часа | `service.apply_mat` | щит героя становится 🔴 |
| Фестиваль: порог 70%, программа на 90 минут, иначе Рейд | `service.FESTIVAL_PROGRAM` | запуск ниже порога честно создаёт Рейд |
| Тихая почта: 3 стикера, +2 СЗ | `routers/student.py` | учитель видит стикер и день, но не автора |
| Генерация 25 учёток, клички без повторов, пароли 12 символов | `service.generate_students`, `nicknames.py` | второй запуск не повторяет уже выданные клички |
| Карточки с QR на печать | `components/Cards.tsx` | `@media print` оставляет на бумаге только сетку карточек |

## Безопасность

- Пароли — bcrypt. Учитель видит сгенерированный текст ровно один раз, при
  создании; дальше только сброс.
- Реестр «кличка → имя» лежит зашифрованным (Fernet). Ключ — в окружении
  сервера, не в базе. Каждое открытие записи требует свежий код 2FA и пишется
  в журнал.
- Второй фактор учителя — TOTP (RFC 6238), совместим с любым приложением-
  аутентификатором.
- Ученик не может: сменить кличку, логин или пароль, увидеть чужую Карту
  героя, загрузить файл, написать кому-либо. Проверено тестами на границы
  ролей — все учительские эндпоинты отвечают ученику 403.
- Экспорт CSV содержит только клички. Настоящих имён в выгрузке нет.
- Все SQL-запросы параметризованы (`$1, $2 …`), конкатенации пользовательского
  ввода в SQL нет ни в одном месте.
- В шаблоне уведомления родителю нет ни клички ребёнка, ни чужих данных.

## Решения, которые пришлось принять

Несколько мест ТЗ допускали больше одного прочтения. Выбор сделан так:

1. **«1 СЗ = 1%» и класс из 25 человек.** Буквально это означает, что 100 СЗ
   закрывают Древо целиком — для класса это один хороший день. Поэтому цель
   вынесена в параметр класса `class_target` (по умолчанию 100, ровно как в
   ТЗ). Поставив 1000, получаете осмысленный темп на четверть.
2. **Урон Древу за мат.** В §5 «Древо» написано −5%, в §5 «Анти-мат» — −10%.
   Взят −10% как более конкретное указание (`rules.TREE_PENALTY_MAT`). За
   прогулы остались −5% и −10%, как в разделе про Броню.
3. **2FA по SMS.** SMS-провайдера в школьной установке обычно нет, а заводить
   внешний сервис ради второго фактора — значит вынести персональные данные
   наружу. Сделан TOTP: тот же уровень защиты, ноль зависимостей, работает и
   через Telegram-бота, если он умеет считать код.
4. **PDF-карточки.** Вместо серверной генерации PDF — печатная вёрстка
   (`@media print`) и «Печать → Сохранить как PDF». Учителю на один клик
   больше, зато не нужен ни шрифтовой пакет с кириллицей в контейнере, ни
   ещё одна зависимость, которая умеет ломаться перед самым уроком.
5. **Автоматический детектор мата по стоп-словам** не сделан осознанно:
   ученик в системе нигде не вводит свободный текст (ни чата, ни комментариев,
   ни подписей — это требование §8), поэтому сканировать нечего. Кнопка «Мат»
   у учителя работает.
6. **Голосование за стиль кличек** проходит до создания учёток — когда героев
   ещё нет, голосовать в приложении некому. Итог фиксируется параметром
   `nickname_style` при создании класса. В приложении работает голосование за
   меню чаепития (блок программы Фестиваля).

## Что осталось за пределами кода

- **Выдача бонусов** (отмена проверочной, +15 минут к чаепитию, право вето)
  происходит в классе. Система показывает, что бонус открыт, и помнит это —
  исполняет его учитель.
- **Уведомление родителю** формируется как текст, который учитель копирует.
  Отправкой система не занимается: рассылка родителям — это отдельный
  контур с отдельными согласиями.
- **Журнал действий** (`audit_log`) не чистится автоматически. Требование
  «хранить 7 лет» он выполняет с запасом; удаление по сроку — вопрос политики
  школы, и делать его молча за спиной у администратора неправильно.
- **Домен и сертификат.** `https://guild.<школа>.ru` и wss поверх него — это
  сертификат на вашем nginx или reverse proxy перед ним. Без HTTPS браузер не
  даст ни установить PWA, ни открыть wss.
